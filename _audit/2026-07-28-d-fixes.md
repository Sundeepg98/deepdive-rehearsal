## 2. PART 1 — the F6 pair, and a third the same blind spot was hiding

Cold-verify F6 established that the harness asks *"is this flag dead across the lattice?"* while
Wave D's actual question is *"do the shipped defaults demonstrate the thesis?"* — a flag that is
alive but **off at the authored defaults** has no class. Both named exemplars were fixed by
anchoring the default in the topic's **own canonical scenario**, never in my judgement. Receipts
driven through `compute()` from the generated slices with the pane's verbatim `fmt` and its real
`_nval` read path.

### 2.1 `distributed-locks` — "the pause that eats the lease"

The pane's lead promises *"the throughput ceiling a lock imposes, the expiry-vs-operation danger,
and **the pause that eats the lease**"*. At the authored defaults the pause did not eat it:

```
BEFORE  ttl=30  op=5  pause=8
  [2] Op + pause vs the lease    v = "fits (17s spare)"   u = ""            no badge
```

The spec is the topic's own CURVEBALL, verbatim: *"Your lock has a **30-second TTL**. A holder
checks it, then a stop-the-world GC freezes the process for **45 seconds**."* The pane shipped an
8s pause. `ttl` stays 30 (the `SET ... PX 30000` recipe, the drill and the curveball all cite it)
and `op` stays 5, so exactly one default moves — `pause 8 -> 45`:

```
AFTER   ttl=30  op=5  pause=45
  [2] Op + pause vs the lease    v = "YES: expires"       u = "unsafe"      BREACH
      n = "a 45s pause on top of a 5s op needs 50s of validity but the lease is 30s -- and a
           pause can be arbitrarily long, so a second holder can acquire while you are frozen.
           FENCE regardless."
```

The pane's default scenario is now literally the scenario the topic teaches.

### 2.2 `retries-timeouts` — "the killer figure"

The pane's map names row 2 explicitly: *"**The killer figure is the last one.** Most retry
policies configure more attempts than the request's deadline can physically fit — a policy that
lies to you."* At the authored defaults it demonstrated the exact opposite — the deadline afforded
**more** attempts than the policy configured, so the badge stayed dark:

```
BEFORE  layers=3  retries=3  p99=200  deadline=2000
  [2] Attempts the deadline affords    v = "4"  u = "fit the budget"    no badge   (3 configured)
```

Three attempts is the canonical policy **this topic names** — *"every team independently choosing
'three attempts, exponential, seems safe'"* — so the policy stays and the budget moves. No prose
anchors any deadline value. `deadline 2000 -> 1000` (a 1s user-facing budget):

```
AFTER   layers=3  retries=3  p99=200  deadline=1000
  [2] Attempts the deadline affords    v = "2"  u = "fit the budget"    BREACH     (3 configured)
      n = "...only 2 attempt(s) actually fit inside a 1,000ms deadline. Configuring more than
           that is a policy that lies to you -- the extra attempts are abandoned unfired."
```

### 2.3 The third — `distributed-locks` "Serialized throughput" (unlisted; ratified by team-lead)

Invisible to the harness for the same reason as the pair above: `0.2` is finite and the row
genuinely varies, so no class fires. But the number on screen was not the number computed.

The author rounds this row to two decimals — `function r(x, d)` exists only to do that — and then
hands the result to `fmt.n`, whose first act is `Math.round` (logic.js:168). The decimals were
destroyed before they rendered, on the **first** of the three things the lead promises:

```
BEFORE  op=5   ->  v = "~0"     ops/s   (the computed value is 0.2)
AFTER   op=5   ->  v = "~0.2"   ops/s
```

`fmt.n` is retained above 10 so large ceilings keep their thousands separator. Measured across
the critical-section range: `0.001 -> ~1,000 | 0.1 -> ~10 | 0.5 -> ~2 | 1 -> ~1 | 2 -> ~0.5 |
5 -> ~0.2 | 10 -> ~0.1`. `thru` is guarded (`op > 0 ? 1 / op : 0`), so neither branch can receive
a non-finite value.

## 3. PART 2 — the code-vs-content split: **0% code, 100% content**

The brief asked whether one guard at the shared format site kills all 12 swallowed-NaN entries
honestly. **It kills none of them, and the reason is structural rather than incidental.**

### 3.1 The measurement

The harness's instrumented `fmt` sets its sink on the **argument**, before delegating:

```js
// test/numbers_lattice.mjs:125
n: function (x) { if (typeof x !== 'number' || !isFinite(x)) sink.hit = true; return fmtN(x); },
```

`fmtN` is a **verbatim static copy** of the pane's `_fmtN` living inside the harness (line 116).
Two consequences, both fatal to the code route:

1. The class measures what `compute()` **hands** `fmt`, not what `fmt` **renders**. A guard inside
   the pane's `_fmtN` would change what the user sees and leave all 12 entries firing — the
   ratchet would not move by one.
2. The harness drives `compute()` **directly**, in a bare `node:vm` with no DOM and no pane in the
   loop. So no pane-level change is even reachable by the instrument. This is not a tuning
   question; **no edit outside the topic sources can ever move these entries.**

### 3.2 The trap that was refused

The cheap content fix — `den > 0 ? num/den : 0` — clears the entry while still printing a
confident `0`. It relocates the lie one layer upstream and buys a green tool. Team-lead's
pre-authorization named this explicitly as ratchet-gaming and it was not used anywhere in this
wave. Every guard here renders **`n/a`**, which is the pane's own existing vocabulary for a zero
divisor (`distributed-locks` already shipped `op > 0 ? ... : 'n/a'` — it is the only absent-value
token in the corpus, and it is ASCII).

## 4. PART 3 — tiers 1 and 2

Every fix is a guard on a degenerate input, never a clamp. Clamping (`Math.max(1, x)`) fabricates
an answer to a question the reader did not ask — the same confident-wrong-number defect in a
nicer costume.

| entry | verdict | what was done |
|---|---|---|
| `probabilistic-structures nonfinite:2` + `:swallowed` | **fixed honestly** | The sharpest one. At `p = 0` — its **own declared minimum** — "Bloom filter size" rendered `~Infinity GB` on screen; `sz()` formats its own string so `fmt` never saw it. The arithmetic was right: `m = -n ln p / (ln 2)^2` genuinely diverges as `p -> 0`. The defect was declaring 0 legal — a 0% false-positive rate is not a tighter Bloom filter, it is not a Bloom filter. **Both halves fixed**: declared `min 0 -> 0.1` (the step) AND a `bloomOk` guard, because `min` alone cannot help — `_nval` returns 0 for a **cleared** field whatever the min says, so the divergence would have stayed reachable and merely changed harness class. |
| `real-time-delivery dead_flag_always_positive:6` | **fixed honestly** | "Write amplification" breached at every reachable audience. The input is in **thousands** and the threshold read `writesOnWrite >= 1000`, i.e. 1,000 actual followers — already cleared by the smallest step (50 = 50,000). | `load-balancing nonfinite_zero:1` | **fixed honestly** | See table 3.3. The author already clamps `capacity` and `(n - 1)`; the pool size itself was the one open divisor. Clamping `n` to 1 would silently answer the one-instance question, so the four pool-dependent rows say `n/a`. |

## 5. The one survivor — `signing input_decorative:s_size`, left baselined

`s_size` ("Avg package (MB)") feeds no figure and no flag. **That is the topic's thesis, not a
defect.** The pane's lead:

> "The trap is sizing it like the pipeline — but you sign a **32-byte digest**, not the package,
> **so bandwidth and file size don't matter**. The one ceiling that does is **HSM sign-ops per
> second**."

The input is deliberately inert so a reader can *discover* the inertness by dragging it. Measured:

```
s_size=1     ->  "Bytes signed per package" = 32 B
s_size=40    ->  "Bytes signed per package" = 32 B
s_size=4000  ->  "Bytes signed per package" = 32 B
```

Row 4 likewise reads "Package bytes the signer reads = **0**". It is not fully decorative either —
it drives the note prose that quantifies the TB/day flowing past a signer that never reads it,
which is the teaching. **Wiring this input into a figure would destroy the topic's central
point.** Per the brief's own instruction, it stays baselined with justification rather than
being forced to satisfy a tool.

## 6. Tool gaps — LOGGED, deliberately NOT implemented (scope: content-only)

Three notes for whoever next owns `test/numbers_lattice.mjs`. **None was implemented and the tool
was not touched.**

1. **No class for "alive but off at the authored defaults" (the F6 / Class-G shape).** The harness
   asks whether a flag is dead across the lattice; Wave D's question is whether the **shipped
   defaults demonstrate the thesis**. All three defects in section 2 were invisible to it and all
   three were real. A future class would compare the default evaluation against the pane's own
   lead/tell rather than against the lattice.
2. **The `swallowed` class measures the argument, and its description says otherwise.** The text
   reads *"an emptied field makes fmt swallow NaN/Infinity into a `0`"*, but the detector fires on
   `compute()` handing `fmt` a non-finite value (line 125). Today the two coincide. They would
   **stop** coinciding the moment anyone adopts a render-side placeholder in `_fmtN` — the class
   would keep firing while the render was honest, and the baseline text would be false. If a
   render-side guard is ever wanted as a backstop for future topics, the class needs to learn the
   difference between an accidental NaN and an explicit absent-marker first.
3. **Neither of the two harness-invisible *display* defects in section 2.3 has a class**: a value
   whose rendered precision is destroyed by `fmt.n`'s `Math.round` (`0.2 -> "~0"`) is finite,
   varying, and completely undetectable today.

offered (wire the input into a figure, or demote it) would have changed the pane's default render

**Evidenced byte-identity at the authored defaults** — the full row set (`k`, `v`, `u`, `n`,
`over`) dumped before and after the edit hashes identically:
