### 2.1 The defect (pre-fix build)

The **outline** wore the card's own room; the **halo** wore the roomless brand indigo, in every card
and both themes. The neutral is theme-dependent, which the audit's light-only capture did not show —
so this defect had two different wrong colours, not one:

| theme | outline (per card, `--rm`) | halo (all six cards, `--acc`) |
|---|---|---|
| light | the six room hues | `rgb(83,74,183)` @ .15/.20 — `#534AB7` |
| dark  | the six room hues | `rgb(157,147,240)` @ .15/.20 — `#9D93F0` |

Card 1 (messaging-events), light, verbatim:

```
outline    : 2px solid rgb(0, 107, 99) off=2px
box-shadow : color(srgb 0.32549 0.290196 0.717647 / 0.15) 0px 0px 0px 3px,
             color(srgb 0.32549 0.290196 0.717647 / 0.2)  0px 0px 16px -4px
--rm on the element rgb(0,107,99)      --acc on the element rgb(83,74,183)
```

Reproduced by **real `Tab` presses** from a cold home as well as programmatically — tab 1 lands on
messaging-events, tab 2 on data-storage, both showing the same split.

### 2.2 A second half of X10 the audit did not record

`box-shadow` is **one property**. `.hm-room` carries `box-shadow:inset 3px 0 0 var(--rm)` at rest
(`styles.css:2026`) — the 3px room stripe down the card's left edge. Because the generic
`button:focus-visible` supplied the whole property on focus, **the stripe was not overridden in
colour, it was deleted**:

```
REST    box-shadow : rgb(0, 107, 99) 3px 0px 0px 0px inset
FOCUSED box-shadow : <the two neutral glow layers>          <- no inset layer at all
```

Measured `inset=[]` on all six cards in both themes. So focusing a room card did two wrong things:
painted the wrong hue **and** removed the card's clearest room marker. X10 records only the first.

## 4. Contrast: stated, not invented

**The halo is decorative and no contrast gate is added.** WCAG 2.4.7 focus visibility on this
element is carried by `outline:2px solid var(--rm)` with `outline-offset:2px`, which is **unchanged
by this wave** — same width, same style, same colour, same offset as on the pre-fix build. The halo
is a 15%/20%-alpha glow layered on top; it adds emphasis and cannot subtract from the outline.
No contrast threshold moves, so inventing a numeric gate here would be a check with nothing to
measure. `room_contrast.py` continues to own the token side of the palette.

The audit was explicit (§8): *"`focus_ring.cjs` never reads `box-shadow`. All three of its probe

### What the new arms ask

Six new assertions (three questions x two themes), on the `#home` route in fresh isolated contexts:

| arms | assertion |
|---|---|
| 7-8 | `.hm-cta` halo derives from the room it will OPEN — a **regression guard on W15's fix**, which nothing guarded before |
| 9-10 | all six `.hm-room` halos derive from the **card's own** `--rm`, not the roomless `--acc` — **X10** |
| 11-12 | a focused `.hm-room` **keeps its inset room stripe** — the §2.2 half |

**Hex-free, probe-resolved (the W15 pattern).** There is not one colour literal in the arms. A hidden
probe span is appended *inside* the element under test and given the expected declaration through the
**same property** (`box-shadow`), then its computed value is compared to the element's own — same
inherited `--rm`, same engine, same serialisation path. A hardcoded hex here would be a second copy
of the palette that drifts the day a room is retuned.

**It carries its own negative control, every invocation.** The neutral halo the generic rule would
paint is resolved the same way (`var(--acc-a15)`/`var(--acc-a20)` off the same element) and the arm
asserts the halo is **not** that. It also asserts `--rm` and `--acc` genuinely **differ** on the
element and **fails rather than passes** if they do not — otherwise a room whose hue happened to
equal the neutral would green the check for free. That is not theoretical: platform-infra is
`rgb(105,78,176)` against `rgb(83,74,183)` in light and `rgb(173,154,238)` against `rgb(157,147,240)`
in dark, which is also precisely why this defect could sit in a screenshot unnoticed. The arm also
fails closed if the probe itself computes to `none`.
