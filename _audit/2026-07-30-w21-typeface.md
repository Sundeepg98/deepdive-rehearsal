## 1. The defect, and what it actually cost

89 declarations across 16 source files spelled the app's body stack as `-apple-system,sans-serif`.
`-apple-system` resolves on Apple platforms and **nowhere else**, so off Apple the generic wins --
and on Windows the generic `sans-serif` is **Arial**. The stylesheet read as though a system face had
been chosen on purpose; the rasteriser was handed Arial.

Ledgered by the W4 cold verify as **F-2** and confirmed cross-engine by the 2026-07-30 audit (WebKit
and Firefox measure the declared stack byte-identical to a bare `sans-serif`, 332.38px in both) --
a **platform truth, not an engine bug**. On Apple platforms nothing about this wave changes; on
Windows and Linux it changes what every user sees.

Invisible to `latent_arial` **by construction**: that guard asks "does this button carry NO author
family?" These buttons carry one. "Latent Arial is at zero" was true of its ledger and false of the
screen.

### The fix

**One definition, referenced everywhere.** `--sans` now holds the app stack in `src/styles.css`
`:root`, byte-identical to what `body` declared before, beside the `--mono` token that already
proves the pattern reaches shadow roots (custom properties inherit across the boundary; the
`adoptedStyleSheets` BASE_SHEET already consumes `var(--mono)` and `var(--display)`).

- 89 declarations -> `var(--sans)` by codemod, **comments masked**: `styles.css:1797` is prose that
  QUOTES the truncated stack (the W4 F-7 note about `.xd-again`), and rewriting the record of why
  a fix happened is not a fix. One in-comment occurrence existed; it survives byte-for-byte.
- `body` -> `font-family:var(--sans)`.
- `--display` -> `'Space Grotesk',var(--sans)` (it carried its own partial `-apple-system` tail;
  resolution on Windows is unchanged -- Segoe UI either way -- and the display face's fallback is
  now the app stack rather than a third spelling of it).
- **Nothing else changed.** `git diff -- src/` contains no line that is not a family swap or the
  new token comment.

**Why the family list was swapped in place rather than folded to `font:inherit`.** The W3/W4
discipline is `font:inherit` where inheritance is the honest form. It is not honest here: these are
`font` SHORTHANDS, and the shorthand's reset of `line-height` to `normal` is load-bearing against a
`body` that sets `--line-height-loose`. Rewriting them as `font:inherit;font-size:..;font-weight:..`
would have inherited the loose line-height and moved every one of these boxes for a reason that is
not the typeface -- exactly the layout shift the brief calls a STOP. Swapping only the family list
keeps the delta to glyphs and their metrics, which is what the VR attribution below is able to claim.

### The documented exceptions -- two, both argued in place

1. **`src/scripts/app/print-qa.js:9`** keeps the stack as a **literal**. It opens its own
   `window.open()` document; `:root` reaches it only through W16's `tokenBlock()` harvest, and the
   one property that decides whether the sheet is legible at all should not depend on that. A
   literal duplicate is how a stack acquires two answers, so the check **compares** it, normalised,
   against the `--sans` value. Pinned, not trusted.
2. **`styles.css` `.sr-ttl`** -- `Georgia,'Times New Roman',serif`. A deliberate serif masthead on
   the session report, the one place the app speaks in a printed-document voice. A face the app owns
   on purpose, not an unresolved stack.

## 3. The guard: `test/typeface_census.py` -- the ratchet `latent_arial` structurally cannot be

Every `font-family` / `font`-shorthand family list in authored `src/` must be `var(--sans)`,
`var(--display)`, a mono stack, `inherit`, a token definition, or a **named** exception. Registered
in `check_all.py` after `phantom_tokens`. Static, ~1s.

**Scope is what git TRACKS under `src/`.** `npm run build` writes output into `src/` too, and it
carries 186 families nobody here wrote: 185 `"Space Grotesk",sans-serif` are **mermaid's own emitted
stylesheet**, frozen inside the cached diagram SVGs (`tools/compiler/mermaid-cache/*.svg`, byte-frozen
on purpose because mermaid measures text with OS fonts and the build was not otherwise reproducible),
and one `system-ui,sans-serif` sits in minified vendor code inside the esbuild bundle. This is a git
question rather than a path-pattern skip **so it cannot be evaded**: a new file under
`src/topics/_generated/` is out of scope only while it is untracked, and to ship authored CSS you
have to commit it. The check prints both counts (189 scanned, 498 skipped) rather than quietly
scoping itself.

**Watched RED** on the defective tree: `_audit/2026-07-30-w21-typeface-watched-red.txt` -- 91
findings, exit 1. **Green** after: 180 declarations, 0 orphans, 2 exceptions.

### A W4 attribution this wave corrects

W4's F-2 note recorded `.crambtn` as reporting `Arial:1` post-fix and explained it as an unavoidable
single-glyph **icon fallback** -- "their SPECIFIED stack is now the correct app stack". Measured:
39 of the 42 single-glyph rows were **not** icon fallback. They are
`.crambtn:not(.cram-tog)::after` -- the U+203A chevron at 19px -- which carried the **truncated
stack in its own rule**, one of the 89. CDP attributes generated pseudo-element content to the
originating element's node, which is why the button reported `Arial:1` while its own inherited
`font-family` was byte-identical to the app stack in both builds (verified directly: every computed
font property identical, `::before` content `none`, one element child). Those 39 are now Segoe UI.

Only **3** genuine fallbacks remain, all `#homeBtn.tn-step.tn-home` rendering **U+2302** at
`Arial:1` -- its declared stack is the app stack and Segoe UI has no glyph for that codepoint, which
is the definition of an honest fallback. W4 named this one correctly.

**Instrument note:** the probe initially reported a serene, entirely false zero because
`DOM.requestNode` needs `DOM.getDocument(pierce:true)` re-issued after every navigation. It now
ABORTS if any node returns no platform fonts, or if the walk enumerates zero buttons. It also
initially undercounted by 6 because `/^Arial$/` misses **Arial Black**, which is what a
`--font-weight-heavy` rule on the truncated stack rasterises as.

### Is the churn ONLY the typeface? Measured, not asserted

`_audit/w21-typeface-before-after/layout-delta.cjs` walks every element on the six surfaces behind
the 14 baselines (shadow roots pierced), against both builds with the same binary, and classifies
each moved box.

**1792 boxes, 1073 moved: 174 TEXT-SIZED, 898 REFLOW, 1 flagged STRUCTURAL, 0 appeared, 0 vanished.**

The single flag is **explained, not waived**: `m-walk div.app` padding-bottom `80px -> 79px`. `.app`
is `padding-bottom:calc(var(--chrome-bot) + var(--space-8))`, and `--chrome-bot` is written at
runtime by `chrome-metrics.js:97` as `Math.ceil()` of the live mobile dock's height. Measured
directly on both builds: `.mockbtn` **47px -> 46px** (its family went truncated -> app stack, and
Segoe UI's line box at that size is 1px shorter than Arial's), so the dock measured **72 -> 71** and
`--chrome-bot` carried it into the padding. A font-metric consequence travelling through a runtime
measurement -- the classifier flags it only because it reads computed `padding`, which here is
downstream of the metric. **Zero boxes changed geometry for a non-text reason.**

Named reflows, since the brief asks for them by name:

- **The nine `.seg` pane tabs: 44px -> 48px each**, so the strip is **420 -> 456**. Each tab is a
  two-line column (label + sublabel at 10.5px) with auto height; Segoe UI's line box is taller than
  Arial's at that size. Width is unchanged at 260px.
- `.nd-go` **103.91 -> 92.36px wide** -- a shrink-to-fit button; Segoe UI Black is narrower than
  Arial Black for "Start the drill". Pure advance width.
- `#mockopen.mockbtn` 66 -> 64px, `#inttog.inttog` 55 -> 56px.
- The `.crambtn` rows keep their heights exactly (42.80 / 59.59 / 62.00); they move in y only
  because the strip above them grew 35px.
- `sidebar_geometry` still passes its own "7+ pane tabs above the 1280x800 fold" assertion, and
  `fold_budget` passes.

**Framing is asserted, not assumed** -- a review pair that crops its subject out is evidence-shaped

- the strip **overflows the rail it sits in** (456px of strip, ~323px of rail), so "the crop
  contains the whole strip" is not available and is not claimed -- the pair is cropped to what is

## 7. The F-1 residue (W20 freeze section 10.2) -- corrected

`src/styles.css` carried the falsified rationale in its shipped source comment: the
`var(--rm,var(--acc))` fallback described as "what keeps `phantom_tokens.py` honest about a token no
stylesheet declares". W20's cold verify falsified it by experiment -- `--rm` is already defined for
that check by the inline `--rm:` that `panels.js:282` emits, the exact shape `phantom_tokens.py:36-37`
names as legitimate and its self-test asserts must not be flagged, and a deliverable built with the
fallback stripped to a bare `var(--rm)` runs the shipped check byte-identical (`NEW: 0`, PASS).

Corrected in place, with the mechanism, the proof and the provenance
(`_audit/2026-07-30-w20-hue-coldverify.md` F-1), and with the point that the code is right and only
the reason was wrong. This was the third and last live instance, and the one a future wave was most
likely to read, because it sits in the file that wave would open.
