## 1. The contract, and how it was held

The audit parked P3-10/P3-11 with a specific warning: do not open "a wave that changes many
pixels for no felt improvement." This wave therefore builds token STRUCTURE with **zero visual
movement by construction**, and the zero is asserted three independent ways, not hoped for:

| claim | how it is proven | result |
|---|---|---|
| no pixel moves in the shipped surfaces | VR 16/16 baselines byte-identical | see section 7 |
| no pixel moves under the density toggle | a computed-style A/B with a negative control, because **no gate check has ever set `data-density`** | see section 6 |
| every token equals the value it replaced | each of the 110 replacements resolved back to a number and compared | 0 mismatches |

**Value normalisation stayed out of scope.** Collapsing 35 tracking values to two or three, or
the home stack's 24/16/18/26/30/26/26/20 to one rhythm, is a design judgement the audit
deliberately parked. This wave does not pre-empt it. What it delivers is the thing that judgement
was missing: a countable set, one file to edit, and a guard that stops the set regrowing while it
waits.

## 3. The token map

All tokens flow through the generator (`design-tokens/tokens.json` ->
`src/tokens.generated.css`, which is GENERATED and gitignored and was never hand-edited).

| group | tokens | shape |
|---|---|---|
| `track.px.*` | 20 | literal, e.g. `--track-px-0-3: 0.3px` |
| `track.em.*` | 14 | literal, e.g. `--track-em-0-08: 0.08em` |
| `track.none` | 1 | `0` |
| `gap.home.*` | 8 | alias, e.g. `--gap-home-header: var(--space-24)` |
| `measure.home` | 1 | alias, `--measure-home: var(--space-980)` |
| **total** | **44** | |

Naming follows the file's own established dash-decimal convention (`--size-font-16-5`), with
`neg-` for negatives. Aliases use DTCG references (`{space.24}`) so Style Dictionary's
`outputReferences` emits `var(--space-24)` rather than flattening to `24px` -- which is what
keeps the density scale working (section 6).

### Why a value-named tier is not `--space-N` all over again

This is the obvious objection and it deserves a direct answer, because the audit's complaint
about the spacing layer applies verbatim to any value-named tier: `--space-19/39/43` "exist only
because someone once wrote 19/39/43px", and `var(--space-13)` "looks disciplined and means 13px,
chosen ad hoc."

The difference is structural, and it is enforced, not asserted. The space scale was minted
**speculatively** -- every integer 1 to 20 whether used or not -- and nothing ever removes a rung.
The tracking tier is **mint-on-use**: `tracking_census.py` FAILS on a `--track-*` token that
nothing references. The set is therefore exactly the set the app renders, provably, today. That
is a property `--space-N` has never had and cannot claim.

## 4. The guards (2 new gate arms: 71 -> 73)

Both mirror the `phantom_tokens` / `typeface_census` discipline: a long argued docstring, a
ratchet, and a **self-test that aborts** rather than report a green it did not earn. This repo
has shipped four checks that could not fail; neither of these is allowed to be the fifth.

### `test/tracking_census.py` -- 6 arms

1. **LITERAL** a raw length. The ratchet.
2. **FOREIGN TOKEN** tracking sourced from outside the `--track-*` family.
3. **DRIFT** `var(--track-x, FB)` where the fallback disagrees with the token.
4. **UNDEFINED** a `--track-*` reference no token file defines.
5. **ORPHAN** a `--track-*` token nothing uses. *This is the arm that makes the tier honest.*
6. **EM REGISTRATION** an `@property --track-em-*` in the built deliverable.

Arm 6 is a zero-pixel tripwire guarding a live mechanism. `tools/postprocess-tokens.mjs` emits
`@property` for tokens matching `--space-N` / `--size-font-N` / `--z-*` / `--duration-*` /
`--line-height-*` / `--font-weight-*`. A **registered** `<length>` computes at its *declaration*
site, so `@property --track-em-0-08{syntax:"<length>"}` would resolve `.08em` against `:root`
once and every uppercase label in the app would stop tracking its own type size -- pixels moving
in a build whose token file did not change. Measured in section 6: the difference is 0.88px vs
1.28px on 11px type. The em tokens are deliberately unregistered and this arm keeps them that
way. (Verified: 113 `@property` lines before and after this wave -- none of the 44 new tokens
matches any of the six regexes.)

### `test/home_rhythm.py`

Requires each column member's gap to be its **own** registry slot and each measure to be
`--measure-home`. Checking the token *family* alone would not be enough: three slots resolve to
the same 26px, so `--gap-home-section` on the decision hero would render byte-identically and
read as correct forever, while the token file quietly asserted that the hero and the topic
library are one role.

**Scope is derived, not declared.** A block is in scope exactly when it declares the content
measure -- i.e. when it is a member of the home column. The property that puts a block in the
column is the property that puts it in scope, so both arms cover one population.

**The boundary was corrected by the check itself, on its first run.** Scoping by selector alone
(`#home` / `.hm-*` with any non-zero margin) discovered two sites my hand-written list had missed
and that do *not* belong: `.hm-h{margin:0 0 var(--space-12)}`, a heading's gap to its own body,
and `.hm-cta-d{margin-top:2px}`, a two-pixel optical nudge on text *inside* the hero button.
Demanding a `--gap-home-*` role name for a 2px nudge is exactly the noise an all-src gap ratchet
would have been. `#home .ix-foot` left scope for the same reason. Both corrections are pinned as
self-test fixtures so they cannot be undone quietly.

**Why not an all-src gap ratchet:** `gap:` and `margin:` appear in the hundreds in this
stylesheet, overwhelmingly component-internal, where a primitive is the *right* answer and a
semantic name would be ceremony. Such a ratchet would fire constantly, mean nothing, and be
switched off within a month. The census surveyed the stylesheet for other candidate runs and
found 7; only one (the topic route's `--space-830` column) is the same shape, three are partial,
two are not really runs, one is a counter-example. The home stack is the audit's own exemplar and
a complete self-contained surface. Scoping to it is what makes the green mean something.

## 6. Zero pixels under density -- the hole VR cannot see

The censuses turned up a fact that changes what "VR is green" is worth: the density path is
**shipped, user-reachable, and entirely unexercised by the gate**. `shell.js:286` binds the `D`
key to cycle `default / compact / cozy`; the shortcuts overlay advertises it; 126 declarations of
live CSS ride on it in the committed deliverable. **No check anywhere in `test/` sets, reads or
asserts `data-density`** -- so no VR baseline, contrast run or layout smoke has ever been taken
at compact or cozy.

That matters here specifically, because `--space-980` is in the density-scaled set (compact
804px, cozy 1127px). A semantic layer that flattened its aliases would have silently frozen the
home column width and VR would not have noticed.

Measured directly, with a **negative control** because a probe that cannot fail proves nothing:

```
[default] margin 24px vs 24px | max-w 980px vs 980px | ls 0.88px vs 0.88px | textW 88.6094 vs 88.6094  => IDENTICAL
[compact] margin 20px vs 20px | max-w 804px vs 804px | ls 0.88px vs 0.88px | textW 88.6094 vs 88.6094  => IDENTICAL
[negctl]  margin 20px vs 23px                                                                          => DIVERGENCE DETECTED (probe can fail)
```

The alias tracks the density override exactly (24 -> 20, 980 -> 804), and the em token resolves
at the **use** site: 0.88px on 11px type. An `@property`-registered one would have given 1.28px
against `:root`, which is the failure arm 6 exists to prevent.

The mechanism is not novel here -- the shipped `--font-size-body: var(--size-font-14)` semantic
tier is already `@property`-untyped for the same reason. This wave follows a proven pattern; it
now also measures it.

- **c2** was cross-checked against `home_rhythm.py`'s own parser-driven discovery, which

**A guard hole the review process closed before any child saw it.** The first draft of
`home_rhythm` accepted *any* `--gap-home-*` token at *any* slot. Since three slots resolve to the

one role. The slot-identity arm was added *before* the migration briefs went out, and a swapped
name is now a self-test fixture.

**What made the slices closed-form:** each brief carried a defined input, a verifiable output
path, restated house rules, an explicit trap list (the three `--space-26` decoys; `--space-20`
appearing as both a gap and a padding on one line; comment prose that must not be rewritten), and
self-verification steps with the numbers to expect. Migration children were told to write a
script rather than hand-edit, because 110 hand edits is 110 chances to typo a value into a silent
pixel change.

**File-disjoint by construction:** c3 owned `src/scripts/`, c4 owned `src/styles.css` +
`src/tw.css`, and each was told the other was live and must not be touched. Two writers on one
file is the one unrecoverable state.

## 9. Found, recorded, deliberately not fixed

Honest residue, so a future pass inherits it rather than rediscovering it:

- **`.hm-cta-d{margin-top:2px}`** -- a raw literal inside the home block. `--space-2` exists and
  equals it. Out of this wave's derived scope (not a column member), and invisible to any audit
  that greps for `var(--space-`.
- **`.hm-tele{padding-top:var(--space-20)}`** -- padding, so out of scope by the letter, but it
  sits under a `border-top` divider with a 26px gap above it. The *perceived* rhythm around that
  rule is 26 above / 20 below. A normalisation pass that touches only the G1 margins will leave
  the divider visually off-centre.
- **Spacing tokens acting as layout measures.** `--space-980` and `--space-830` are content
  column widths riding the *spacing* density scale, so the reading column narrows to 804px in
  compact. `--measure-home` names that for the first time; whether a measure should scale with
  spacing density is a design question, now askable.
- **The density path has no gate coverage at all** (section 6). Not this wave's to fix, but it is
  the largest unguarded surface the censuses touched.
- **`--size-font-16-5` gets no `@property`** -- its name fails `--size-font-\d+` and its value
  fails `(\d+px)`. The only size primitive in the file with no registered type.
