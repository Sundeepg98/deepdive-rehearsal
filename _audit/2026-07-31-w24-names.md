## Verdict

The seven findings are fixed, and every one of them is verified BY EAR on the built deliverable,
not by asserting that an attribute exists. Across the home, the topic route, all ten panes and
four overlays, the number of controls whose accessible name carries a decorative glyph went from

Two things came out of doing it that are worth more than the fixes:

1. **The two name paths disagree, and only one of them is the one the reader hears.** This decided
   the entire shape of the wave -- see below. It also means an `aria-label` is not a general fix
   for glue on this app, and a browser check asserting on the accessible name would have certified
   these controls green while a real screen reader glued them.
2. **The first re-drive caught this wave's own fix.** The kicker/description separator shipped as a
   period, and NVDA spoke it: `ATTRIBUTE BOUNDARY dot A schema-flexible`, on every card. That is
   the audit's F7b defect, reproduced by the fix for its sibling. Both captures are kept.

## The measurement that decided the fix shape

Chromium's accessible name for a room button, read over CDP off the committed pre-wave
deliverable, against what NVDA said for the same control in `at1-d1`:

```
Chromium accname   "1 Messaging & Events 7 topics * 0 of 7 started 0% drilled"
NVDA (at1-d1 C-home-tab-04)
                   "1Messaging and Events 7 topics 0 of 7 started 0 percent drilled, button"
```

The space after the numeral is in one and not the other. Chromium's accname algorithm inserts a
space at a block-level boundary; NVDA is reading the flattened text, which does not. The audit saw
the same split from the other side and named it (F10: one read carries the U+203A chevron and one
does not -- "one name from the accessibility API and one from the flattened virtual-buffer text --
two sources, not two app events").

The consequence is concrete: **a fix that only lands in the accessible name is invisible to the
reader that found the bug.** What lands in both is a real character in a real text node.

Confirmed after the fix, in this wave's own capture -- the accname reads `"1 , Messaging & Events"`
(with the engine's heuristic spaces around it) while NVDA reads `1,Messaging and Events`. The
reader never sees the engine's space. Only the authored comma is common to both.

## The separator pattern -- decided once, applied everywhere

**One primitive.** `.nsep`, declared twice (once in `src/styles.css` for the light DOM, once in
`BASE_SHEET` for the seventeen shadow hosts, because global CSS does not cross the boundary):

```css
.nsep{position:absolute!important;width:1px;height:1px;margin:-1px;padding:0;
      overflow:hidden;clip:rect(0 0 0 0);clip-path:inset(50%);white-space:nowrap;border:0}
```

**One character: a comma.** Three properties had to hold, and each was measured rather than assumed:

- **It must be a real text node, not an `aria-label`.** See above -- the accname path is not the
  path the reader uses for these controls.
- **It must not be whitespace.** The walkthrough's model-script summary already authored a literal
  space at exactly this kind of seam (`sounds like <span class="sub">`) and was still heard as
  `sounds likemodel script`: whitespace at a block boundary is collapsed away. The app had already
  tried the obvious fix and lost.
- **It must not be a period.** A period reads better on the page, and it was the first choice at
  the kicker/description seam. NVDA substitutes the word "dot" for a period not followed by
  whitespace -- and its flattened text does not carry the space the separator holds. Drive 1 heard
  `ATTRIBUTE BOUNDARY dot A schema-flexible` on every card. In the same capture the comma was
  spoken **zero** times while still doing its job. Drive 2, after the change: zero spoken "dot",
  zero spoken "comma".

**Zero reflow by construction.** `position:absolute` means it is never a flex or grid item, so it
never contributes to `gap`; 1x1 plus clip means nothing paints. Verified against all 16 VR
baselines, including the drill and walkthrough panes where the shadow-root sites live.

**Twelve sites** carry it: the six room buttons; all three seams of a topic card; weak chips;
refresh pills; the companion relation cards; the cram sheet's one-liner; the focus timer; the
drill's probe nav; the walkthrough's arc steps; and the model-script summary.

### The four fix shapes for glyphs, and why there are four

Each is chosen by what is provably zero-reflow at that site:

| Situation | Fix | Why not something simpler |
|---|---|---|
| an existing decorative span | `aria-hidden="true"` | attribute only; nothing can move |
| a bare glyph in a NON-flex container | wrap in an `aria-hidden` span | an inline box is inert here |
| a bare glyph in a FLEX/GRID container | `aria-label` on the control | a new child becomes a flex item and replaces the literal space beside it with a `gap` -- an accessibility fix with a visual regression |
| CSS generated content | two `content` declarations: the plain one, then the alt-text one | an engine without alt-text support drops only the second, so the glyph still paints and nothing regresses where the feature is missing |

## The static ratchet -- `test/at_name_hygiene.cjs`, registered

**Watched-red, on the shipped check against the pre-wave tree** (`git archive 8b2599b src`, the
final 50-assertion check run against it):

```
at_name_hygiene: 3/50 assertions, 9 + 2 mutants all detected
FAILED 47 assertion(s)

  3 [nsep]       the primitive is absent; no separator is EXACTLY ", "
 12 [sep]        no authored separator at any of the twelve composition sites
 25 [glyph]      the decorative-glyph inventory is inside nameable subtrees
  2 [toggle]     two toggles state their condition twice
  5 [collision]  the Cram family shares one name; three header keys are in the name
```

The 3 green are arm D's corpus guards, which are correctly green before the wave: nothing had been
rewritten yet. That is the arm whose whole job is to stay green.

**Why it is a source check and not a browser check.** Asserting on Chromium's accessible name would
have reported these controls green while a real reader glued them -- a check whose reference comes
from the system under test, which is the failure this gate's own header warns about. What survives
both name paths is a real character in a real text node, and that is a property of the source. It
also means the check is platform-deterministic and never SKIPs: no browser, no fonts, no pixels.

**Four arms.** (A) an authored separator at each of the twelve sites, the primitive genuinely
off-screen, and every separator EXACTLY `", "` -- markup and the DOM-built one alike. (B) the
decorative-glyph inventory out of every nameable subtree, plus the toggles. (C) the two families
that collided. (D) **the accidental-repair guard** -- the audit's binding rule made mechanical: it
fails if a separator is authored into the corpus, or if either receipted description string is
edited away instead of the markup being fixed.

**Eleven mutants, every run**, and it aborts rather than reporting a green it did not earn: strip
every separator; make one whitespace-only; a period at ONE site; a period at ALL twelve; a bare
space at the DOM-API site; let the primitive paint; un-hide the glyphs; collapse the Cram names;
put the header keys back in the name; rewrite the corpus; leak a separator into it.

The four period/space mutants exist because the cold verify broke arm A with them. Its first
version asserted only "non-whitespace", and a period is non-whitespace -- so drive 1's exact
defect, the one thing this whole wave turns on, could be reintroduced at every site with the gate
green. Two lessons, both kept: a check should pin the specific finding it was built for, not a
generic property near it; and a scan of `class="nsep"...>text<` cannot see a separator built with
`createElement`, so the twelfth site needed its own read.

Honest limit: the mutation arm only bites once the tree is green -- on a red tree a mutant trivially
produces failures. It is meaningful from this commit onward.

One false positive was found and fixed while writing it: a bare `nsep` substring match flagged
three clean corpus files, because the corpus contains the word "inseparable".

## Deferrals, stated so they are not mistaken for oversights

- **Composition sites left alone.** The seg strip, the topic switcher trigger and its menu rows,
  the mobile companion `<summary>` and the drill's setup disclosure all compose names the same way,
  but the audit files them under "working well" -- they sit on separate rendered lines, so the glue
  never fires -- and Wave A's row does not name them. They remain heuristic-dependent. The primitive
  is now in both stylesheets, so widening to them later is a one-line change per site.
- **The room buttons' meta run-on.** `... 7 topics 0 of 7 started 0 percent drilled` is still one
  unpunctuated breath. P2-3 names the numeral seam, which is what is fixed; the run-on is the
  second half of the audit's own F5 and is a separate call about how much a room button should say.
- **`AP Is`, `s 3`, `UR Ls`.** NVDA's acronym splitter. The audit recommends accepting it and
  spending nothing; nothing was spent.
- **The accname carries a cosmetic double space** (`"1 , Messaging & Events"`) where Chromium's own
  heuristic space lands beside the authored comma. It is silent in speech, and visible only in
  braille or an API dump. Removing it would mean moving the separator into CSS generated content,
  whose reach into the flattened-text path is exactly what is unproven -- trading a proven fix for
  a cosmetic gain. The app already ships one of these (`Text size 116 percent , largest`, P3-8's
  sibling nit).
