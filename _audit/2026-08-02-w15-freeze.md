## 2. THE TWO TAIL FIXES, WITH THEIR MEASUREMENTS

### T1 -- THE HOME PRINT

Cycle 4's R5 stopped `print-qa.js` from taking Ctrl+P on the home -- correctly, because
`openPrint()` read `TopicRegistry.current()`, the BOOT constant on a route with no topic. Handing
the route back to the browser's own print was only half an answer: nobody asked what the browser
prints there. Driven at 1280x900, A4, `preferCSSPageSize`, on the shipped build:

```
home, fresh (no cram ever opened)          3 pages / 391,415 bytes  -- the BOOT topic's cram sheet
home, after visiting saga's sheet, closed  6 pages / 872,924 bytes  -- SAGA's cram sheet
AFTER THE FIX                              2 pages / 143,721 bytes  -- the record itself
```

Two causes one line apart in `@media print`: `.app{display:none !important}` (right for a topic
route, whose panes are shadow DOM and print blank -- the entire reason the cram substitution
exists) and the cram force-show carrying no `.open` requirement, so a CLOSED dialog printed.

**The named fix was `body:not(.print-session) .cram-ov.open`, and it was DEVIATED FROM, with the
measurement that forced it.** That is the right sentence one scope too wide: on a TOPIC route the
never-opened sheet IS the printable artifact, and `print_truth.cjs` ARM F owns it as a P1. Built
with the wider form:

```
#walk, cram never opened:  3 pages / 391,447 bytes  ->  1 page / 1,048 bytes
print_truth:  FAIL [file-print] a never-opened sheet still renders to paper  sections=0
```

Scoped to the home instead. `:not(.open)` is kept rather than flattened because an OPEN sheet on
the home is a REACHABLE state -- driven both doors (`location.hash` and the Home button), a topic
left with the sheet up lands on `#home` with `.cram-ov.open` still true and on screen.

The chrome hidden with it was derived from the page. `.hm-rail` and `.hm-tabs` are `position:fixed`
bars at the 680px A4 content box and would repeat on every sheet; `.hm-skip` is a preference
checkbox. `#scrolltop` was checked and LEFT (opacity 0, and a child of `<body>`, not `.app`).
`.hm-status` is the one that is not chrome -- it carries the shaky/missed split nothing else on the
page carries -- but it was fixed, so "probes graded" extracted from the 2-page PDF on pages
**[1,2]**; un-fixed, it flows once, and re-measured it is on page **[2]**.

`print-qa.js:109`'s home early-return is untouched, as ruled.

## 8. CI -- THE BRANCH GATE DID NOT FIRE, AND THAT IS STRUCTURAL

Pushed clean: `2696291..9676596  appeal/w15-refinements -> appeal/w15-refinements`.
**No CI run exists for this branch.** `gh run list --branch appeal/w15-refinements` returns `[]`.

The reason is not a misconfiguration to chase. For a `push` event GitHub Actions resolves workflow
definitions **from the ref being pushed**, and this branch was cut from `2696291`, which is
**11 master commits before** the branch gate existed:

```
workflows on THIS branch     deploy-pages.yml                    (on: push: branches: [master])
workflows on origin/master   battery, ci-exec, deploy-pages, engines, gate, nightly,
                             previews, warm-pool
gate.yml was added by        99e72d0 "ci(dump-everything): windows+macos runners, branch gates,
                             cross-engine smoke, previews, caches"
```

`workflow_dispatch` cannot substitute, and the API says so for the same reason -- it resolves the
definition from the ref too:

```
gh workflow run gate.yml --ref appeal/w15-refinements
  HTTP 422: Workflow does not have 'workflow_dispatch' trigger
```

**Nothing was imported to force a run, deliberately.** Copying master's `gate.yml` onto a frozen
branch would have meant (a) landing non-doc changes after the run of record, which is the rule this
freeze already broke once and re-ran to honour, and (b) importing a workflow whose windows leg
invokes `test/ci_shard_gate.py` -- a file that does not exist on this branch -- so the only thing it
would reliably have produced is a red that says nothing about this work. And master's
`deploy-pages.yml` is not a usable substitute in either direction: it PUBLISHES to `gh-pages`, so
dispatching it against this ref would push unmerged work to the live site.

**It arrives free at integration, with no action needed.** Master's gate is
`on: push: branches-ignore: [master]`, so the first push of this branch once master's workflows are
in its tree -- i.e. after the integrator merges master down -- fires the ubuntu + windows advisory
gate automatically. By that workflow's own doctrine that is the correct order anyway: *"certification
remains the conductor's local win32 serial gate at freeze and the merged-tree run at train. A red
here is an early tripwire, not a veto; a green here is strong but not the record."* The
certification this freeze owes is section 7, and it is green on a clean committed tree.

## 10. ARCHITECT BEAT

### HARVEST -- what is now reusable beyond this wave

**A print surface needs a POSITIVE list, not a hide list.** Every print defect in this wave and its
verification was the same shape: a rule that correctly hid what it was thinking about, and a
`<body>`-level element nobody enumerated. `.app` was hidden and the cram sheet printed; the cram
sheet was scoped and the scroll disc printed; the disc was hidden and the Topic index printed.
Three rounds, three overlays, one mistake. The arm now asserts the body-level paint SET equals
`['div.app']`, which is the only form that could have caught all three at once -- and the exclusion
it needs (1x1 `aria-live` announcers) is NAMED rather than sized away, so it stays sharp.

**"One gate, not a patch per key" has a corollary nobody wrote down: enumerate the listeners, not
the keys.** R6 was right that one gate beats four patches -- and it created F3, because the
argument was about KEYS while the risk lived in a second LISTENER. `grep -rn addEventListener.*keydown src/`
is the sweep that would have caught it the same day.

**A compensation must be measured, not declared.** T2 removed an accessible name and named three
compensations in source. Two held; the third was a live region the press path destroyed, so the
compensation was structurally incapable of compensating. The rule this yields is cheap: **when a
fix removes a channel and names a replacement, drive the replacement in the same commit.**

**`aria-disabled` is advisory, and test tooling disagrees.** Playwright's actionability check
treats `aria-disabled="true"` as disabled and will hang 30s on a `locator.click()`. The control is
genuinely still pressable by a real user, so the honest instrument is `click({force:true})` --
asserting through the actionability check would be asserting Playwright's opinion instead of the
app's behaviour. Worth knowing before the next ruled-pattern rollout.

### PATTERN -- what keeps recurring

**The wave's own fixes are its richest defect source, one layer down.** Of six defects found after
the tail fixes, **four were created or newly exposed by this wave's own work**: the 44px box moved
the focus ring (R8), the boot gate left the chord behind (F3), the removed name left a dead
compensation (F2), the `.app` exemption newly exposed two `<body>` children to paper (F1, F8). This
is now consistent enough to plan around: **after any fix that MOVES a thing -- to a new rect, a new
lifetime, a new authority -- sweep for what was left at the old one.** Cycle 4's closing pass said
this in one sentence and it kept being true afterwards.

**A receipt built by RECONSTRUCTION is the one that fails re-derivation.** Every disputed figure in
this wave (D-1, D-2, D-4, the three chip ranges) was assembled from an earlier measurement of a
different state rather than measured against a counterfactual built for the purpose. The verifier's
method -- plant the pre-change declarations into a mirror, run ONE probe against both builds -- is
the one that reproduced to the tenth of a pixel. **A before/after table whose BEFORE was not taken
by the same probe as its AFTER is a claim, not a measurement.**

**Coverage gaps are shaped like verbs.** Everything the hunt found lived where the checks had
nouns: the goal strip was READ by three checks and PRESSED by none; the sheet was checked for what
was ABSENT and never for what was PRESENT; the boot window was DRIVEN for four keys and not for the
chord. `grep -rn "data-goal" test/` returning only `getBoundingClientRect` and `.focus()` was
visible from orbit, and nobody ran it.

### SCAR -- what this cost, and what it should cost next time

**The `print_truth` interplay is the sharpest one.** The named fix for T1 was
`body:not(.print-session) .cram-ov.open` -- the right sentence, one scope too wide -- and building
it took the topic route's file-print from 3 pages to 1 page / 1,048 bytes and reddened
`print_truth` ARM F, a P1 guard from another wave. It cost one build to discover and would have
cost a shipped regression if the named fix had been applied on faith. **The scar: before narrowing
a shared rule, grep the checks that already own the surface.** `print_truth` had documented that
exact behaviour as intentional, in prose, in the file, and reading it first would have produced the
scoped fix directly. The corollary held twice more in this pass: `.ix-ov` went to the unconditional
line and `.scrolltop` did not, and both scopes came from measuring the OTHER route rather than
generalising from the one where the defect appeared.

**The press gap is the expensive one, because it was cheap to see.** A control this wave rebuilt to
44px, moved the focus ring on, hoisted onto every record class, and put in front of every new user
-- across four cycles and a closing pass -- and **no check ever pressed it**. Two arms measured its
box and one measured its ring; none measured what happens when a user uses it. That is how a live
region that could never fire shipped as the stated compensation for a removed accessible name, and
how a clamp stayed silent through 77 green checks. **The scar: when a wave TOUCHES an interactive
control, the gate must DRIVE it, not measure it at rest.** Geometry arms are not interaction arms,
and this wave had four of the former and zero of the latter on the one control it spent the most
time on.

**The `pinTop` timer has now cost three probes** (cycle 3's 57px coin flip, cycle 4's
coordinate-click, this pass's false-negative on F1). It is recorded three times and has never been
fixed, because the honest fix is a product decision about whether `data-autofocus` should scroll at
all. Until then, **any probe that scrolls the home must wait the 400ms window out and read the
scroll back** -- which the new arm does, and says so.

**One process scar, already paid once in this wave.** The first post-verify gate run was
invalidated by an uncommitted `_audit/` path created a minute after it started -- the same rule
cycle 4 wrote down after spending three runs on trees that no longer existed, broken again in the
pass that quotes it. Two runs were spent on this pass's freeze for the same reason. The rule is not
"be careful"; it is **finish every edit, commit, THEN start the gate** -- and it is cheap to obey
and expensive to remember.
