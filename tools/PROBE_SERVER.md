# The probe server

One warm Chromium, held open, probed over localhost HTTP. Built because every probe an agent runs
against the deliverable was paying for a browser launch plus an 11.7 MiB parse, and probe-heavy
agents make 50-116 of them.

**Adoption is OPT-IN.** Nothing in `test/` calls this, no gate depends on it, and `check_all.py` is
untouched. It is a tool agents may pick up, not a change to how the repo is verified. That stays
true until a cold verify has gone over it independently.

```
node tools/probe_server.cjs --port 9377          # start it (holds one browser)
node tools/probe_client.cjs --eval 'document.title' --fresh
node tools/probe_client.cjs --shutdown           # stop it, and its browser
```

---

## The measured win

From `tools/PROBE_SERVER_RECEIPTS.txt`, regenerated by `tools/probe_server_test.cjs`. Medians over
15 representative measurements on an 8-core dev box.

| per probe | quiet box | with 4 cold boots running at once |
|---|---|---|
| `/eval` against the held world | **11 ms** | **16 ms** |
| `/reload` then measure (fresh world) | **1199 ms** | -- |
| cold launch + parse + measure + teardown | **2566 ms** | **2956 ms** |

- held-state probe: **~233x** a cold boot
- fresh-world probe: **~2.1x** a cold boot

The quiet-box ratio is the pessimistic one, and deliberately so: what a warm browser avoids is
exactly the cost that inflates when a fleet is running. Under contention the cold column has been
measured from 2.9s up to 5.3s while the warm column moved from 11ms to 16-28ms.

The fresh-world path only wins ~2x because it still re-parses the document -- that is the price of
a real reset, and it is the right price to pay (see below). The 233x is the exploration path.

## The contamination discipline

A warm browser is a **shared mutable world**. That is the entire speedup and the entire hazard: the
moment two measurements share a page, the second is measuring whatever the first left behind. A
fast probe against a contaminated world is worse than a slow probe against a real one -- it is
**wrong at speed**.

> **Assertive** measurements -- geometry, contrast, fold membership, anything a verdict rests on --
> **must** run behind `/reload`, in a world nothing has touched.
>
> **Eval-against-held-state** is the fast path for **exploration only**, and it is **opt-in**.

This is enforced by default, not documented and hoped for:

1. **`/eval` defaults to `mode: "assert"`**, which is refused with **HTTP 409** unless the world is
   pristine. Measuring a dirty world means passing `mode: "explore"` and saying so on the record.
2. **A MutationObserver attributes DOM mutations to the probe that caused them.** An assert-mode
   probe that mutates anything flips the world to dirty, so the *next* assert probe is refused. The
   discipline survives an author who believed their expression was a pure read and was wrong.
3. **`/viewport` dirties the world on purpose.** An app that booted at 1280 and was resized to 390
   is not the app a phone gets -- one-shot boot measurements and cached layout decisions still hold
   the desktop's answer. Use `/reload {"viewport":"390x844"}`, which builds the world at that size.

**Every response is stamped**, so a verifier can audit what a measurement trusted without taking
anyone's word for it:

```json
{"world_id": 12, "since_reload_ms": 9, "probes_since_reload": 1,
 "pristine": true, "mutations": 0, "mutation_detail": []}
```

`probes_since_reload: 0` is a fresh world. `probes_since_reload: 47` is whatever the previous 46
probes left behind -- and now it says so out loud, in the receipt, after the fact.

**"Fresh" means a new browser context, not just a navigation.** A navigation resets JS globals but
keeps localStorage, sessionStorage and cookies -- and this app persists theme, stars and notes, so a
bare reload would hand the next measurement the last one's saved state. `{keep_context: true}` opts
into the weaker reset and is labelled weaker in the response.

`/reload` also does not return on the load event. It returns when the app is ready and then
genuinely **at rest** -- nothing in flight -- using the at-rest primitive `require`d from
`test/_boot.cjs`, so there is one definition of "still" in this repo and this tool cannot drift from
the gate's.

## Adopting it in an existing probe script

```js
// BEFORE
const browser = await chromium.launch(B.launchOpts());
const page = await browser.newPage({ viewport: { width: 1280, height: 800 } });
await B.gotoApp(page, HTML);
const v = await page.evaluate(() => document.querySelector('#homerail').getBoundingClientRect().width);
await browser.close();

// AFTER
const { withFreshPage } = require('./tools/probe_client.cjs');
const v = await withFreshPage((p) => p.eval('document.querySelector("#homerail").getBoundingClientRect().width'));
```

The expression is a string rather than a closure, because it crosses a wire. Everything else --
launch flags, readiness predicate, at-rest settle -- is identical to what the gate does.

```js
const { probe, reload, withFreshPage, screenshot, ProbeError } = require('./tools/probe_client.cjs');

await withFreshPage(async (p) => {
  const rect = await p.eval('document.querySelector("#hometabs").getBoundingClientRect()');
  await p.screenshot('/tmp/phone.png');
  return rect;
}, { viewport: '390x844' });

await probe('document.querySelectorAll(".ix-card").length', { mode: 'explore' }); // exploring
```

Catch `ProbeError` and check `.contaminated` to tell "you measured a dirty world" from "your
expression threw".

### Endpoints

| endpoint | does |
|---|---|
| `/eval` | `{expr}` or `{body}`, `mode: assert\|explore`, optional `arg` |
| `/reload` | fresh context + load + ready + at rest; `{viewport, url, keep_context, settle_scope}` |
| `/goto` | `{path}` -- a path, a URL, or `#hash`; a navigation is a new world |
| `/screenshot` | `{path, viewport?, selector?, full_page?}`; returns bytes + sha256 |
| `/viewport` | `{w,h}` resize **without** reload -- dirties the world by design |
| `/status` | url, uptime, probes served, pristine, published launch args |
| `/shutdown` | stop the server and its browser |

### Returning values

The expression's value crosses the wire as JSON, normalised **in the page** so `getBoundingClientRect()`
arrives as real numbers rather than `{}`. Things that cannot cross -- a DOM node, a function -- come
back as a **named error** telling you what to return instead, never as a silent `null`. `NaN` and
`Infinity` survive as `"__NaN__"` / `"__Infinity__"` rather than becoming `null`, because a null
width is the most believable wrong answer a layout probe can give.

## Verifying it yourself

```
node tools/probe_server.cjs --port 9377 &
node tools/probe_server_test.cjs --port 9377 --cold-repeats 3
```

Measures 15 representative values **twice** -- once through the server behind `/reload`, once
through a cold Chromium launched and torn down per measurement -- and requires them to be
**exactly** equal (geometry as full floats, no rounding; styles as exact strings). Current state:
**15/15 identical, screenshot byte-identical**, and 5/5 trials of the mutate-refuse-reload cycle.

Three things in that test are worth knowing about, because each one caught a real defect while this
tool was being built:

- **The reset proof runs 5 times, not once.** The first mutation guard subtracted a sampled noise
  floor that read 0 or 1 depending on the frame, so it missed a real one-mutation contamination in
  2 runs out of 3. A single-shot proof was a coin flip dressed as evidence.
- **A pure read must leave the world pristine** (the negative control). A guard that dirtied on
  everything would pass a catch-only test while refusing every honest measurement.
- **A measurement carrying no information fails the run.** `vacuous()` rejects all-zero rects and
  empty collections -- it caught two rows of this very test comparing 0 against 0 and printing
  MATCH, which is this repo's signature failure mode reappearing inside the test written to certify
  a new tool.

## Limits

- Loopback only, single client, no auth. `/eval` runs arbitrary JavaScript in the page **by design**
  -- that is what a probe server is. Do not bind it to anything but 127.0.0.1.
- Parity is proven for 15 representative measurements on a quiet box, not for all measurements
  under all conditions. Anything depending on wall-clock time or animation phase is where warm and
  cold could still part company.
- The server holds one page. Requests are serialised; it is not a pool.
